# FXseek 手机版 · 桌面端接口协议

> 这份文档写的是**已经跑通并实测过**的行为，不是设计意图。
> 每一条请求/响应都是在本机上真跑出来的，可以直接照抄。
> 规划与决策在 [`手机版规划.md`](手机版规划.md)；这里是给写 iOS 客户端的人看的。

- 桌面端代码：`mobile.py`（新模块，纯增量）+ `app.py` 里的接线
- 当前状态：**M1/M2 桌面端已完成**；M3.5 的 EG2 向量同步（第 7 节）尚未实现
- 前提：局域网模式下，桌面端的库**不离开局域网**。手机每次检索都由电脑算完再把结果发回去。

---

## 1. 发现：Bonjour

桌面端一开局域网就挂上广播，**没有引入任何新依赖** —— 用的是 macOS 自带的 `/usr/bin/dns-sd`。

| 项 | 值 |
| --- | --- |
| 服务类型 | `_fxseek._tcp` |
| 域 | `local` |
| 实例名 | 电脑自己的名字（如 `范老板的MacBook Pro`、`FA的Mac mini`） |

> ★ **实例名不再固定叫 `FXseek`**（2026-10-12 改）。同一个 Wi-Fi 下开两台电脑时，
> 两条一模一样的 `FXseek` 根本分不出谁是谁，点错了就配错机器。
> 实例名与下面的 `name` TXT 都走 `mobile.py` 的 `host_label()`：
> `scutil --get ComputerName` → `scutil --get LocalHostName` → `socket.gethostname()` → `platform.node()`
> → `"FXseek"`，取到第一个非空就用，并缓存（`scutil` 只跑一次）。
> **`/Applications/FXseek.app` 的项目名特意还叫 `FXseek.app`，没跟着改** —— 免得弄乱 `open -a` 和 Dock 里那条。

TXT 记录：

| 键 | 例 | 说明 |
| --- | --- | --- |
| `name` | `范老板的MacBook Pro` | 电脑名，客户端列表里显示的就是它（超长会折两行） |
| `ver` | `1.1.0` | 桌面端版本，用来提醒「版本差太多」 |
| `items` | `350` | 素材总数，手机上先显示个大概，不用等第一次请求 |
| `api` | `1` | **协议版本**，见下 |

`api` 是给以后的兼容用的：手机发现 `api` 比自己认识的大，就该提示用户升级 App，而不是发一堆自己看不懂的请求。

手机侧用 `NWBrowser`（Network.framework）或 `NetServiceBrowser` 都行。**发现不到不算错误** —— 很多家用路由器/访客网络会挡 mDNS，所以配对界面必须保留「手输地址」这条路（地址形如 `http://192.168.1.7:8231`，端口是桌面端设置页里显示的那个）。

## 2. 鉴权

### 2.1 两条铁律

1. **回环永远放行**：来自 `127.0.0.0/8` 和 `::1` 的请求一律不鉴权。桌面端自己的界面、菜单栏助手都走这条路，开不开局域网都不受影响。
2. **局域网模式下，所有 `/v1/*` 都要令牌**。例外只有三个白名单：
   - `GET /health`
   - `GET /v1/about`
   - `POST /v1/pair/request`（还没配对的手机得能敲到它）

### 2.2 带令牌

两种头都认，**优先 `Authorization`**：

```
Authorization: Bearer <token>
X-Fxseek-Token: <token>
```

没带或带错 → **401**：

```json
{ "error": "还没配对，或令牌已失效", "need_pair": true, "service": "_fxseek._tcp" }
```

看到 `need_pair: true` 就该回配对界面，不要重试。

> ★ 服务端校验令牌用的是 `secrets.compare_digest`（防计时攻击），而且比的是 **bytes** 不是字符串 —— 所以手机上随便带个中文/表情令牌也只会得到干净的 401，不会把连接搞崩。

### 2.3 配对

配对码在**电脑上**生成：设置 → 手机连接 → 「换一个」。也可以 `POST /v1/pair/code`（只认回环）：

```json
{ "code": "380874", "expires": 1791549334, "ttl": 300 }
```

手机拿码来换令牌：

```
POST /v1/pair/request
Content-Type: application/json

{ "code": "380874", "name": "iPhone 15" }
```

成功 **200**：

```json
{
  "ok": true,
  "token": "51ABbRm8…（43 字符）",
  "device": {
    "id": "3f0325de7801badf",
    "name": "iPhone 15",
    "created": 1791549034,
    "last_seen": 1791549034,
    "from": "192.168.1.7",
    "token_hint": "51ABbR…KRuc"
  }
}
```

失败 **401**，`error` 直接可以显示给用户：

| 情况 | error |
| --- | --- |
| 码不对 | `配对码不对（还可以试 N 次）` |
| 试错满 5 次 | `配对码不对，已锁定 60 秒` + `retry_after: 60` |
| 还在锁定期 | `试错太多次了，请等 N 秒后再试` + `retry_after: N` |
| 电脑上还没生成过码 | `电脑上还没生成配对码，请在「设置 → 连接」里点「显示配对码」` |
| 码过期（超 5 分钟） | `配对码已过期，请在电脑上重新获取` |

**配对码是一次性的**：换到令牌之后立刻作废，同一个码再用回 401（不然一台手机配完，码在剩余有效期内还能再配第二台）。令牌存进 Keychain，之后一直用它。

### 2.4 只在电脑上能用的四条

`GET /v1/mobile/state`、`POST /v1/pair/code`、`POST /v1/pair/revoke`、`POST /v1/mobile/lan`

手机（**哪怕已经配对成功**）碰它们一律 **403**：

```json
{ "error": "这个接口只在本机可用" }
```

理由：这几条改的是「谁还能连进来」。丢一台手机不该等于把整个局域网入口交出去。

### 2.5 设备管理

`GET /v1/pair/devices` 回 `{devices:[…]}`。**永远不回完整令牌**，只有 `token_hint`：

```json
{ "id": "37a06c561b665a10", "name": "机器甲",
  "created": 1791548214, "last_seen": 1791548214,
  "from": "192.168.1.7", "token_hint": "zWZGjc…_eTo" }
```

`POST /v1/pair/revoke` `{id}` 撤销一台；`{}` 或省略 `id` 撤销全部（只认回环）。撤销后那台手机的令牌立刻失效（401）。

## 3. 能力自述

```
GET /v1/mobile/caps
```

```json
{
  "api_version": 1,
  "service": "_fxseek._tcp",
  "name": "FXseek",
  "version": "1.1.0",
  "levels": ["L0", "L1", "L2"],
  "has_ai_desc": true,
  "has_asr": true,
  "has_align": false,
  "item_count": 24,
  "sources": 1,
  "paired": false
}
```

| 字段 | 手机拿它干什么 |
| --- | --- |
| `levels` | 这台电脑现在能提供几级检索。只有 `L0` 说明没配 AI，手机就别显示「搜画面」 |
| `has_ai_desc` | 有没有 LLM 打标 → 支不支持「用大白话搜画面内容」 |
| `has_asr` | 有没有转写文字 → 支不支持搜歌词/台词 |
| `has_align` | 有没有逐字时间轴 → 支不支持「歌词跟着唱」式的逐字高亮 |
| `item_count` | 空库时显示引导，而不是一个空白列表 |
| `paired` | 手机自己带令牌问的时候，`true` 表示令牌还有效 |

`caps` 需要令牌，但**回环不需要** —— 桌面端设置页也读它。这个端点在 `_QUIET_PATHS` 白名单里，不算「用户在操作电脑」，不会把闲置自动打标/转写/对齐的计时清零。

## 4. 深度外派检索

```
POST /v1/mobile/search
```

这是手机唯一需要「问电脑」的检索接口。三种入参，**正好对上手机上那三个入口**：

```jsonc
{ "q": "夕阳 海边", "top_k": 20 }          // 文字搜
{ "image": "<base64>", "top_k": 20 }        // 拍照即搜
{ "audio": "<base64>", "top_k": 20 }        // 录音即搜
```

可选的 `kind`（`image` / `video` / `audio` / `document`）限定类型，`top_k` 上限 **100**；文字那条还可以给 `tier`（默认 `deep`）和 `lexical`。

`image` / `audio` 都接受裸 base64，也接受 `data:image/jpeg;base64,…` 这种 data URL。

### 响应

三种入参**回同一个形状**，手机只需要一套解析：

```json
{
  "query": "小狗",
  "used": "text",
  "tier": "deep",
  "total": 2,
  "items": [
    {
      "path": "/Users/fa/Documents/FXseek示例素材/小狗(示例).png",
      "name": "小狗(示例).png",
      "kind": "image",
      "score": 1.3112,
      "size": 859686,
      "ts": null,
      "why": "画面相似",
      "exists": true,
      "thumb": "/v1/thumb?w=320&path=%2FUsers%2Ffa%2F…"
    }
  ],
  "took_ms": 783
}
```

| 字段 | 说明 |
| --- | --- |
| `used` | `text` / `image` / `audio` —— 回应是走的哪条路，方便你排查 |
| `tier` | 文字那条实际下沉到了哪一级（`fast`/`vector`/`deep`），图/音为 `null` |
| `score` | 分数**只在同一次返回内部可比**，跨查询没有意义。别拿它当百分比显示 |
| `ts` | 视频命中的是**哪一帧**（秒）。视频封面要用它 —— `GET /v1/thumb?path=…&t=<ts>` |
| `why` | 命中原因，见下。手机上直接显示在结果卡片上，用户才知道为什么它排第一 |
| `thumb` | 已经拼好的相对地址，**直接拼到 base URL 上 GET**，不用自己编码路径 |
| `took_ms` | 服务端耗时，用来决定「要不要给用户看一眼转圈」 |

`why` 的取值：

| 值 | 什么时候 |
| --- | --- |
| `画面命中 12.3 秒那一帧` | 视频按画面命中，带具体时间点 |
| `画面命中` | 视频命中但没有帧时间戳 |
| `画面相似` | 图片 |
| `音频内容相似` | 音频（文字搜到的） |
| `内容相似` | 文档 / 其它 |
| `画面像你拍的那张` | 拍照即搜的每一条 |
| `听到的是同一段声音` | 录音即搜的每一条 |

### 错误

| 状态 | 情形 | body |
| --- | --- | --- |
| 400 | 三个入参一个都没给 | `{"error": "至少要给一个：q（文字）/ image（base64）/ audio（base64）"}` |
| 400 | 图片解不开 | `{"error": "图片解析失败：…"}` |
| 401 | 没令牌 / 令牌失效 | 见 2.2 |
| 500 | 检索本身炸了 | `{"error": "检索失败：…"}` |

录音搜不到时**不是错误**，是 200 + 空列表 + 一句解释：

```json
{ "query": "", "used": "audio", "total": 0, "items": [],
  "note": "这段录音太平稳，提不出有区分度的指纹（试着录长一点、带上人声或音乐）",
  "took_ms": 120 }
```

看到 `note` 就直接显示，别自己编一套说法 —— 后端这句和前端的口径是同一份。

### 实测耗时（M1 Mac mini，350 个素材的库）

| 场景 | 耗时 |
| --- | --- |
| 文字，首次（要载 2 GB 的 WeMM 模型） | 3.4 s |
| 文字，模型已载 | **0.78 s** |
| 拍照即搜 | **1.0 s** |
| 录音即搜（指纹） | **0.06 s** |

文字那条的首次延迟主要在载模型。桌面端默认闲置 5 分钟就把模型卸掉还内存，所以隔久了再用会再等一次。

## 5. 可以直接复用的桌面端接口

这些不是为手机写的，但协议稳定、局域网下同样受同一个鉴权保护，手机直接用：

| 用途 | 接口 |
| --- | --- |
| 列表 / 瀑布流 | `POST /v1/browse` `{kind, limit, sort, source}` |
| 详情 | `GET /v1/detail?path=<urlencoded>` |
| 缩略图 | `GET /v1/thumb?path=…&w=320&t=<秒>` |
| 播放（音频/视频，支持 Range） | `GET /v1/file?path=<urlencoded>` |
| 读文本类文件 | `GET /v1/text?path=…` |
| 索引源列表 | `GET /v1/sources` |

**缩略图尺寸**：`w` 会被夹到 `[160, 1200]`，默认 560。手机按自己的屏幕密度要就行；`w` 进缓存 key，同一个文件的不同尺寸各缓存各的，不会互相顶掉。

**播放**：`/v1/file` 支持 HTTP Range，可以直接喂给 `AVPlayer`，拖动进度条不用等整个文件。原文件永远在电脑上，手机只是拉流。

## 6. 桌面端设置页

设置 → **手机连接**：

- 局域网连接：关 / 开（关机状态只有本机能访问）
- 地址：`http://192.168.1.7:8231`（手机手填用）
- 配对码：6 位，5 分钟有效，用一次作废
- 已配对的设备：名称、令牌提示、来源 IP、最近使用时间，各自一个「撤销」

拨开关会让桌面端**重建监听**（绑定地址在建监听那一刻定死，改不了）：旧实例关掉、新实例架起来，中间不让进程退出。实测两次切换后进程都活着，mDNS 相应地挂上/撤下。

## 7. 还没做的

### EG2 向量同步（M3.5）

```
GET /v1/mobile/vectors?since=<rev>&dim=256
→ { model: "eg2-300m", dim: 256, rev: 43,
    vectors: [ {path, vec: "<base64 int8>", mtime} ],
    deleted: ["<path>", …] }
```

**目前没有实现。** 它是「手机上离线也能搜」的唯一途径，但需要桌面端先做两件事：

1. 装 EG2（EmbeddingGemma 2，Apache 2.0；文本档 191 MB / 全模态档 567 MB）
2. 建一份 `eg2_vectors` 表，**和现有的 WeMM 向量并存**

★ 为什么不能用现有的向量：WeMM-Embedding-2B 和 EG2 是**两个不同的模型、两个不同的向量空间**。桌面端的 WeMM 向量喂给手机上的 EG2 检索器只会得到一堆噪声。手机要的是「手机自己也能算出来的那种向量」，所以桌面端必须用**同一个模型**再算一遍全库。

在这条做完之前，手机只做 **L0（文件名/标签）** 本地检索；想要语义检索就走第 4 节的深度外派。

## 8. 桌面端实现备忘

给以后改这块的人：

| 文件 | 位置 |
| --- | --- |
| `mobile.py` | 全部手机相关逻辑：发现、配对、令牌、设备表 |
| `app.py` | `_bind_host()`、`mobile_restart_server()`、`mobile_caps()`、`mobile_state()`、`mobile_search()`、`Handler._lan_gate()`、`Handler._mobile_post()` |
| `settings.html` | `#sec-phone` 那一节 + `loadLanStatus()` / `lanToggle()` / `lanNewCode()` / `lanRevoke()` |

三个必须记住的坑（都是实测踩出来的）：

1. **开关一拨进程就死**。切绑定地址要把旧实例 `shutdown()` 掉，这会让 `run_server` 里的 `serve_forever()` 返回 → `main()` 结束 → 进程退出，把刚架好的新监听一起带走。修法是 `_SRV["rebind"]` 标记 + `run_server` 尾部守候循环「没有活实例**且**没有正在重开」才返回。
2. **非 ASCII 令牌把连接搞崩**。`secrets.compare_digest` 对含非 ASCII 的**字符串**直接抛 `TypeError`，而 `_lan_gate` 在 `do_GET` 最顶上、不在任何 try 里，于是连接被掐掉、客户端只看到「空响应」。改成比 `bytes`，并给校验套了保险。
3. **轮询端点必须进 `_QUIET_PATHS`**。`/v1/mobile/state` 和 `/v1/mobile/caps` 都在里面。不加的话设置页一开就每几秒把闲置计时清零，自动打标/转写/对齐**永远不会触发**。
