# 许可证（免费版 / 专业版）

> **这份文档里有几处标着「⚑ 待拍板」的，是商业决定，不是技术决定。**
> 代码已经把机制留好了，数字和条款你定了告诉我就行，改一处配置就能生效。

手机端 **FXseekMobile 始终完全免费**，不做任何限制 —— 它是获客入口，不是商品。
收费只发生在电脑端，而且**只卡两处用量**，功能不加锁、不降级、不弹广告。

## 一、两档的差别

| | 免费版 | 专业版 |
|---|---|---|
| 索引源 | **3 个** | 不限 |
| 素材条数 | **5000 件** | 不限 |
| 语义搜索 / 以图搜图 / 以音搜音 | 完整 | 完整 |
| AI 描述、音频转写、增强对齐 | 完整 | 完整 |
| 手机端联动（配对、同步、端侧检索） | 完整 | 完整 |
| 离线可用、隐私（不联网） | 完整 | 完整 |

> 「素材条数」数的是**不同的文件**（`COUNT(DISTINCT path)`），不是向量条数。
> 一个视频会拆成几十个单元，拿向量条数去比，用户会看到「我才 30 个视频怎么就 3000/5000 了」——
> 那是在骗人。

**超额时的行为**：不是报错、不是删东西、不是功能禁用。
已经在库里的素材照旧刷新（改个文件名、换个封面都跟得动），只是**不再往里加新文件**，
并在完成后告诉你「另有 N 个没进索引」。索引源超了同理 —— 只挡新增，
列表里已有的目录重新添加、改大小写都不拦。

⚑ **待拍板**：`3 个源 / 5000 件` 是不是你要的数？改 `wemm_app/license.py` 顶部的
`FREE_MAX_SOURCES` / `FREE_MAX_ITEMS` 两个常量即可，全项目只有这一处。

## 二、为什么是「签名码」而不是明文码

明文码（`FXSEEK-PRO-2026` 这种）有三个致命伤：

1. 流出去一份，**全网通用** —— 没人会去举报，你也拦不住；
2. 用户把本机那个文件里的档位改成 `pro` 就绕过了 —— 一个记事本搞定；
3. **没法按客户发不同的码**，「这码是谁泄露的」永远查不出来。

签名码把「授权什么」写进载荷，再用**只有你手上有的私钥**签一遍；
App 里只放公钥。用户能改本地文件、能删文件，但**改不出一个合法签名**。

> ★ 说句实话：`app.py` 在 `.app` 里是明文 Python，真有决心的人还是能改。
> 这套东西的目标是**拦住顺手牵羊**、让愿意付钱的人付得心服口服，不是「绝对锁得住」。
> 所以别按「锁得住」来定价。

## 三、你（开发者）怎么签发

### 1. 生成密钥 —— **一辈子只做一次**

```bash
cd wemm_app
./venv/cpython-3.11/bin/python3.11 tools/gen_keys.py
```

私钥写到 `~/.fxseek-keys/private.key`（权限 600），公钥打印出来。
把公钥填进 `license.py` 的 `PUBLIC_KEY_B64`。

> ⚠️ **私钥务必备份**（丢了你再也签不出能用的码）。
> ⚠️ **私钥永远不要进 git、不要进安装包、不要发给任何人。**
> `.gitignore` 已经兜了一层（`*.key`、`fxseek-keys/`）。
> ⚠️ 换公钥会让**所有已经发出去的码全部失效** —— 一旦发过货就别再动。

### 2. 给客户签一张

```bash
# 永久
python3 tools/make_license.py --serial 客户缩写 --log ~/.fxseek-keys/issues.tsv

# 一年期
python3 tools/make_license.py --days 365 --serial 客户缩写 --log ~/.fxseek-keys/issues.tsv
```

输出就是那个码，形如：

```
FXK1-AEAQA-BQAAB-YVOY5-CTMB6-…-ZSEML-AE
```

151 个字符，**以粘贴为主**（不用指望用户手抄）。

- `--log` 会往 TSV 里追加一行「时间 / 备注 / **码内序列号** / 档位 / 天数 / 码」——
  **一定要留档**，不然半年后客户说「我的码不灵了」，你连他买没买过都不知道。
  ★ 那一列「码内序列号」是关键：码里那 6 字节是随机的，`--serial` 只是你手写的备注。
  有码流出去时 `--inspect` 只能解出随机序列号，拿它去 TSV 里 grep 就能查到是谁 ——
  少了这一列，你就有一串码但不知道属于谁。
- `--inspect <码>` 可以把一个码解包出来看（时间、档位、序列号、是否验签通过），
  客户报问题时用它一眼分辨「码不对」还是「他改过」。

⚑ **待拍板**：卖**永久**还是**年费**？两条路代码都通，`--days 0` 就是永久。

## 四、用户怎么激活

设置与备份 → **许可证** → 粘贴码 → 「激活」。
验签全在本机完成，**不联网**（这软件本来就不联网）。
激活后那个码存在 `~/Library/Application Support/FXseek/license.txt`，
每次启动**重新验签** —— 不信任文件里的任何字段。
换机器就再粘一次；「移除本机许可证」会立刻回到免费版（已建好的索引不会删）。

⚑ **待拍板**：要不要**绑定机器**（一个码一台机器）？
现在的实现是**不绑**（永久码可以自己多台用）。绑的话麻烦得多
（重装系统、换电脑都要找你），而且用户很反感。
我建议**不绑**，靠「码是唯一的、泄露了能追到序列号」来约束。

## 五、和 `COMMERCIAL.md` 的关系（别搞混）

这是**两条不同的轴**，卖的时候别说混了：

| | 管什么 | 谁需要 |
|---|---|---|
| `LICENSE`（PolyForm Noncommercial）+ `COMMERCIAL.md` | **源代码的商用权** | 公司/个体户拿去用、打包进产品、做 SaaS |
| 本页的免费版 / 专业版 | **软件里的用量上限** | 个人用户想把索引源和素材条数放开 |

**专业版许可证 ≠ 商业授权。** 一份「解锁不限量」的码，不会给公司任何
使用这份代码的商用权利 —— 那要走 `COMMERCIAL.md` 的流程单独签。
反过来，拿了商业授权的人，也仍然可以只用免费额度。

UI 文案已经按这个口径写了（不替你做价格承诺，只说明「专业版去掉两个上限」）。
