# FXseek 本地媒体库

用户电脑上有一个 **FXseek 媒体库**，里面索引了他们自己的图片、视频、音频和文档。
它做的是**语义检索**：可以用「有气球的画面」「下雨天的街道」这种自然语言描述找到文件，
也支持用一张图找相似的图、用一段音频找同一首歌。

**你的任务通常是先找到文件路径，再对它做后续操作**（打开、重命名、整理、加工、引用）。

## 什么时候该用它

✅ **该用**：
- 「帮我找上次那张有小狗的图」「我的素材里有没有日落的照片」
- 「找个合适的背景音乐」「有没有讲财报的文档」
- 「把那张图打开 / 复制到桌面 / 改名」← 先搜到路径，再操作
- 用户给了模糊描述，但文件就在他们自己的素材库里

❌ **不该用**：
- 用户说的是网上的东西（那是 `web_search`）
- 用户要给的是具体路径（直接读文件，不用搜）
- 用户问的是代码库里的文件（那是 `glob`/`grep`）

## 核心用法

### 1. 用文字找（最常用）

```
search_media(query="有气球的画面")
```

中文自然语言直接写，**不要**翻译成英文，也**不要**拆成关键词堆砌。
推荐写法是「**主体 + 场景/动作**」：

| ✅ 好 | ❌ 差 | 为什么 |
|------|------|--------|
| `有气球的画面` | `气球` | 太短，噪音大 |
| `小狗在草地上跑` | `dog running grass` | 库里是中文描述，英文匹配差 |
| `日落的风景` | `日落 黄昏 夕阳 风景` | 关键词堆砌反而不如一句话准 |

常用参数：
- `kind`：限定类型，可选 `image` / `video` / `audio` / `document`
- `top_k`：默认 10。不确定就多要几个（`top_k=20`），反正返回是精简过的

**`search_media` 只按内容排，完全不看文件名。** 顺序来自「文件里到底有什么」——
图片的 AI 描述与标签、视频的关键帧、文档正文、音频转写文本。文件名**不参与打分**，
所以不要因为某个名字看起来更贴题就优先推荐它。

### 1.5 按文件名找（只在用户报了名字时用）

```
find_by_name(name="季度报告")
find_by_name(name="2024", kind="document")
```

**只在用户明确说出一个文件名或文件名片段时用它**，例如：

| 用户说 | 用哪个 |
|---|---|
| 「帮我找那个叫**季度报告**的文件」 | `find_by_name` ✅ |
| 「文件名里带 **2024** 的都有哪些」 | `find_by_name` ✅ |
| 「找一下**有气球**的画面」 | `search_media` ✅（这是描述内容） |
| 「有没有**狗在跑**的视频」 | `search_media` ✅ |

**为什么分成两个工具**：用户的文件名经常是随手起的、甚至写错的（「最终版」「稿2」
「未命名-1」），把它混进内容排序会污染结果，让一个名字取得巧的文件压过真正相关的东西。
所以两条路彻底分开 —— 名字归名字，内容归内容，**互不影响**。

两个容易踩的坑：

- **`find_by_name` 不看内容。** 用户说「找有气球的画面」，你调 `find_by_name(name="气球")`
  会得到 0 条 —— 因为那个文件叫 `文件12.png`，名字里没有「气球」，但**内容**里有。
  这种要用 `search_media`。（返回 0 条时工具会自己提醒这一点。）
- **`search_media` 不看名字。** 用户说「找 `季度报告.xlsx`」，你调 `search_media` 是靠猜内容，
  可能找到也可能找不到。用户既然报了名字，就用 `find_by_name`。

未建索引的目录也会被 `find_by_name` 扫到，结果里带 `"unindexed": true` ——
这种文件搜得到、也能打开，但还没建立向量，`search_media` 是找不到它的。

**`"approx": true` = 分词兜底命中，不是精确命中。** 用户记文件名常常只记个大意、
中间还夹着别的字，所以整串匹配落空时工具会再松一层：查询里的字/词有六成在文件名里
就算命中，带 `match_ratio` 表示覆盖比例。实测：

| 用户说 | 库里真实文件名 | 结果 |
|---|---|---|
| `find_by_name("季度报告")` | `季度经营分析报告.docx` | ✅ `approx: true`, `match_ratio: 1.0` |
| `find_by_name("报告")` | `季度经营分析报告.docx` | ✅ 精确（名字里真有「报告」） |
| `find_by_name("气球")` | `文件12.png` | ❌ 0 条（名字里真没有，内容才有） |

拿到 `approx` 的结果时，**把完整文件名念给用户确认**（「找到 `季度经营分析报告.docx`，
是这个吗」），别直接当成他说的那个名字。

### 2. 用图找图 / 用音找音

```
search_by_image(image_path="~/Downloads/参考图.png")
search_by_audio(audio_path="~/Downloads/片段.mp3")
```

`search_by_audio` 走音频指纹，**适合同一首歌的翻录版本**，不适合哼唱找歌。

### 3. 了解库里有什么

```
library_stats()      # 多少文件、多少向量、按类型分布
list_sources()       # 索引了哪些文件夹
list_recent(limit=10)  # 最近上传的
```

**第一次帮用户找东西前，如果不确定库里有没有相关内容，先 `library_stats()` 看一眼。**

### 4. 拿到路径后

```
get_media_info(path="~/Pictures/小狗.png")
```

能拿到 AI 生成的描述、标签、尺寸、时长、命中的视频帧时间等。

## 输出怎么读

搜索结果已经**过滤过相关度**了，只返回真正相关的：

```json
{
  "count": 1,
  "results": [
    {
      "name": "小狗在操场奔跑.png",
      "path": "~/Pictures/小狗在操场奔跑.png",
      "kind": "image",
      "score": 0.95,
      "size": 1258291,
      "info": { "ai_tags": ["小狗","草地","奔跑"], "dimensions": "1312x736" }
    }
  ]
}
```

- **`count: 0` 就是真的没有**，不要降低标准去猜、也不要编造一个路径。
  如实告诉用户「库里没有相关内容」，并可以建议他们换个说法或先添加索引源。
- `score` 是相似度（0~1）。**0.9 以上**基本就是要找的；**0.5 左右**属于弱相关，值得跟用户确认一下。
- **排序只按内容，不看文件名。** 分数来自「文件里到底有什么」——图片的 AI 描述与标签、
  视频的关键帧、文档的正文、音频的转写文本。文件名**完全不参与打分的加成**，因为用户
  的文件名经常是随手起的（「最终版」「稿2」「未命名-1」），照着名字找会找错。
  所以**不要因为某个文件名看起来更贴题就优先推荐它** —— 以 `score` 和 `info` 里的描述为准，
  必要时把 `info.ai_description` / `info.ai_tags` 转述给用户，让他自己判断。
- 如果两条结果 `score` 很接近（尤其是都顶到 0.99），说明它们内容上确实都命中；
  把两者的描述/标签都念一遍让用户挑，不要凭文件名或直觉替他做决定。
- 视频结果可能带 `matched_frame_sec`，表示画面出现在视频的第几秒 —— 用户问「哪一段」时用得上。

## 对话范例

**用户**：「帮我找找有没有适合做封面的大海图片」

```
1. search_media(query="大海 风景", kind="image", top_k=20)
   → 返回 3 条，score 分别是 0.71 / 0.58 / 0.52
2. 挑 0.71 那条，get_media_info() 确认尺寸够大（1920x1080）
3. 回复：「找到 3 张海的图片，最贴合的是 `海边日落.jpg`（1920×1080，
   标签：大海、日落、风景）。另外两张相关度低一些，要看看吗？」
```

**用户**：「把上次那个讲季度财报的文档发我」

```
1. search_media(query="季度财报 经营分析", kind="document")
   → 季度经营分析报告.docx (0.68)
2. 直接把 path 给用户，或按他们的要求打开/复制
```

**用户**：「有没有猫的视频」→ 返回 `count: 0`

```
「库里没有猫相关的视频。」（可以补一句：目前索引了 2 个文件夹，
共 23 个文件，主要是图片和文档。要不要换个词试试，或者把含猫的
文件夹加进索引源？）
```

## 注意事项

- **只读**：这些工具只能查，不能删、不能改、不能导入。要动文件请用普通文件工具。
- **路径是绝对路径**，可以直接交给其他工具使用。
- 索引源之外的文件夹搜不到 —— 如果用户找的东西明显不在结果里，可以提一句「可以
  在 FXseek 的『添加素材』里把那个文件夹加进来」。
- 服务没起来时工具会报连接错误。告诉用户启动 FXseek 媒体库即可，不要自己尝试启动。
- 素材可能是个人照片/录音，**只在用户要求的范围内使用**，不要主动读取内容或扩散路径。
